# Getting help

Start with the [first-study tutorial](docs/guides/first-study.md),
[troubleshooting](docs/guides/troubleshooting.md) and [host support matrix](docs/host-support.md).
The offline Python path needs no provider account; native model sessions do.

Use [GitHub issues](https://github.com/alohays/allagma/issues) for reproducible
bugs, documentation gaps and focused proposals. Include the Allagma release,
Python/OS and host versions, exact command, expected/observed behavior and a small
sanitized example. A failed attempt or digest is often more useful than a long
chat transcript. Do not attach authentication files, private data or entire
runtime homes.

Questions about scientific interpretation should include the independent unit,
protocol, uncertainty assumptions and evidence scope. A workflow audit is not
expert validation of a scientific conclusion. Maintainer support is voluntary;
no response time or managed research service is promised.

Use [Q&A](https://github.com/alohays/allagma/discussions/categories/q-a) for
usage questions, [Show and tell](https://github.com/alohays/allagma/discussions/categories/show-and-tell)
for study reports with limitations, and [Ideas](https://github.com/alohays/allagma/discussions/categories/ideas)
for bounded proposals. The [welcome](https://github.com/alohays/allagma/discussions/13)
and [contributor overview](https://github.com/alohays/allagma/issues/9) link the
available tasks. See [security reporting](SECURITY.md) for sensitive
vulnerabilities and the [code of conduct](CODE_OF_CONDUCT.md) for participation.
