# Allagma 0.3.0rc2 — final qualification in progress

The twelve frozen native sessions have ended. Final evidence review, the
comparison report, real MPS regression and exact-source release acceptance are
still being completed. This version label alone is not a completion claim.
The [acceptance ledger](../v0.3/requirements.md) tracks the remaining evidence.

## Reusable workflow and corrections

The brief/material/resource interface prepares isolated study-owned workspaces
and invokes fresh Codex sessions through pinned methods and adapters. Local
resource supervision retains failed/interrupted attempts, separate setup and
compute accounting, source snapshots and public native usage. Scientific code,
metrics and hypotheses remain study-owned. Default conformance and the toy study
remain offline and standard-library-only.

The frozen rc1 broker supplied MPS high watermark 0.2 but left PyTorch's low
watermark at an incompatible default. The new broker explicitly supplies low
watermark 0.1 while retaining the high cap and disabled implicit fallback.
The actual full-broker GPU check must pass before this path is qualified.

A fast worker could finish after a storage sample and be accepted before its
final footprint was measured. Both supervisors now record final persistent
storage and reject nominal success above the cap. Existing failure reasons are
preserved, with the storage violation also recorded. The same before/after
process fixtures reproduce the old problem and detect the corrected outcome.
The native-adapter fixture uses a fake CLI and does not qualify a hosted model.

The current evaluation scorer accepts the specified inline curve list and the
original path representation. The frozen scorer and its original failures remain
retained. Postprocessing preserves terminal queue evidence and internal aliases,
recognizes named manifest entry lists and streams large archive restoration.
These changes preserve original candidate outcomes and scientific artifacts.

## Migration and evidence boundaries

Record contracts remain version 0.2 and the scaffold remains version 1. Old
bundles/campaigns retain their exact helpers; a new release does not rewrite an
old campaign or remove its failures. Use Check/Plan/Reconcile/Validate/Adopt at
a campaign boundary, or prepare a new research workspace. Paired seed handling
and study-owned minimum confirmation counts introduced in rc1 are unchanged.

Native model configuration remains temporary. No project-level model or review
model override is introduced, and user GUI/personal model choices are preserved.
Scientific computation stays local; model usage uses the existing account.

The comparison estimates the frozen rc1 conditions, including the shared MPS
defect and each candidate's autonomous fallback/repair. It does not estimate the
performance of the corrected GPU path. Original outcomes, later controller
corrections and final release checks remain separately identified.
